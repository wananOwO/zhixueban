# 智学伴 · 技术文档（大纲稿，转 PDF 前充实）

## 1. 项目概述

目标驱动的 Agent 个性化学习平台。痛点：现有 AI 学习工具按教材原结构教学，无法按外部学习目标
（如"参加算法比赛"）对教材做可检查的裁剪、重排与测评。本作品以"受控 Agent 工作流 + 结构化课程
与可验证测评"为核心：每一次课程调整和掌握判断都有依据。

## 2. 需求分析

- 学习者视角：目标外部驱动（比赛/考证/求职），教材内容远超目标范围
- 教师视角：出题须限于已学内容且答案正确；"看过"不等于"学会"
- 工程视角：幻觉防控、不可信生成内容隔离、演示访问边界

## 3. 系统架构

（架构图：解析管线 → 知识图谱 → 编课 Agent → 学习状态机 → 出题/判题 → 掌握度 → 可视化）
单仓库 Next.js 16 全栈；SQLite + sqlite-vec 本地持久化；MCP 只读工具外挂。

## 4. AI 技术方案（评分重点）

### 4.1 Agent 编排与工具调用强制结构化
所有结构化生成（知识点、大纲、题目、校验结论）一律通过 tool calling 提交，
schema 约束不依赖模型自觉遵守提示词。指令遵守差的模型也能输出合法结构。

### 4.2 RAG 策略：教材为中心，可追溯
四级来源分级（主教材/补充库/外部资料/模型生成）；引用锚点 [src:章节:段落] 可跳回原文；
不承诺"接 RAG 即无幻觉"，而是让来源可检查。

### 4.3 出题：生成—校验—发布
校验器独立调用（不给生成上下文），核实参考解法实际知识依赖 ⊆ 已解锁集合；
编程题参考解必须经执行器跑通测试用例才入库。题目质量验证与用户答案判分分离。

### 4.4 判题：执行器为主、LLM 为辅
客观题本地比对；编程题 Judge0/node:vm 沙箱跑测试用例；LLM 只解释错误、给四级分层提示。

### 4.5 掌握度模型
m' = 1-(1-m)×0.5（对）/ m×0.5（错），exp(-Δd/30) 时间衰减，≥0.8 掌握；
掌握证据区分"独立作答"与"使用提示"。

### 4.6 MCP 集成
@ai-sdk/mcp createMCPClient；首版仅只读工具（名称黑名单过滤写操作）；
失败降级不阻塞；调用过程 UI 可视化（Agent 活动面板）。

## 7. 创新点

3. 三模式共享学习记录，随时切换；"做完"与"达标"分离
