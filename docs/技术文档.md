# 智学伴 · 技术文档

## 1. 项目概述

智学伴是一个按学习目标重组教材的 AI 学习助手。用户导入教材、写下目标（例如「参加蓝桥杯 Python 组」），Agent 读完教材后生成一条先修路线，再逐个知识点写课件、出题、批改。

它要解决的问题：现有 AI 学习工具要么照着教材目录讲，要么脱离教材自由发挥。前者不贴合目标，后者无法检查对错。智学伴的做法是让每一步都可以检查：

- 课件里每一句讲解都带出处（来源、章节、段号、原文引文），引文必须与原书逐字一致才能保存。
- 每道题都先过校验，编程题的参考解必须在隔离判题服务里跑通。
- 「学过」和「学会」分开记：学会要靠独立答对不同的题。

## 2. 需求分析

| 角色 | 需求 | 对应设计 |
|---|---|---|
| 学习者 | 目标来自外部（比赛、考证），教材内容远多于目标 | 按目标选知识点，补齐先修，跳过无关章节，并写明理由 |
| 学习者 | 想核对 AI 说得对不对 | 段落级出处，点旁注打开原书并定位 |
| 教师视角 | 题目只能考学过的内容，答案必须正确 | 生成与校验分离；编程题以执行结果为准 |
| 评委 | 公网上能直接试用，又不泄露自己的 Key | 线上模式：Key 只在浏览器与服务器内存；示例课程免 Key 浏览 |

## 3. 系统架构

单仓库 Next.js 16 全栈应用。前端页面在 `src/app/(app)`，后端只有一个入口 `src/app/api/verified-learning/v1/[[...path]]/route.ts`，业务逻辑在 `src/lib/verified-learning/`。数据存在 SQLite（WAL 模式），所有表都以 `scope_id` 隔离空间。

```
教材上传 → 解析（TXT/MD/EPUB/PDF/DOCX/MOBI/AZW3）→ 章节与段落（稳定段号）→ 来源快照（不可变修订）
目标 + 资料 → 课程草稿 → 生成任务（Agent）→ 方案审核（路线图、问题清单）→ 课程版本
学习会话 → 活动调度（课件 / 题组 / 补练）→ 生成任务（Agent）→ 作答 → 判分 → 掌握证据
```

后台任务（`vl_jobs`）带租约与心跳，进度事件写入 `vl_job_events`，前端经 SSE（`/jobs/{id}/stream`）实时显示，断线后按 `Last-Event-ID` 续传。

## 4. AI 技术方案

### 4.1 工具驱动的 Agent

生成用 pi-agent-core 实现的 Agent，所有产物都通过工具调用提交，不解析模型的普通文字回复：

- 读资料：`list_sources`、`search_sources`、`read_source`（按章节分页，返回真实段号）。
- 联网补充：`search_web`、`fetch_web_source`。网页正文保存为可回查的资料，同样按段落引用。
- 提交：`submit_curriculum_point`、`plan_lesson`、`submit_lesson_section`、`submit_question`。
- 验收：`finish_generation`，检查覆盖与完整性，通过才结束任务。

每个提交工具先校验再保存。校验失败时，工具把具体原因返回给 Agent（例如「引用原文与第 761 段不一致」），Agent 修正后重新提交。这样指令遵守较差的模型也能产出合法结构。

### 4.2 出处与防幻觉

引用格式为 `{sourceId, sourceRevision, chapterId, paragraphIndex, quote}`。保存前逐条核对：来源存在且属于本课程，段号存在，`quote` 是该段原文的子串。课件页用二元组覆盖率把引文定位到具体句子，只在那一句下画朱批线。

资料按来源分开：上传的教材、Agent 联网补充的公开网页。补充资料在方案审核时单独列出，用户认可后才进入课程。

### 4.3 课程方案与审核

Agent 提交知识点与先修关系后，`compileCurriculum` 检查空目标（EMPTY_TARGET）、未知知识点（UNKNOWN_KNOWLEDGE）、先修成环（PREREQUISITE_CYCLE）、排除了必需先修（EXCLUDED_PREREQUISITE）、顺序违反先修（INVALID_ORDER）、缺来源（SOURCE_GAP）、引用不合法（INVALID_CITATION）、未认可的补充资料（SUPPLEMENT_NOT_APPROVED）。审核页把这些问题逐条列出，用户可以调整目标、自报已掌握、排除、改顺序、改先修（需写原因）。没有问题时才能确认。

### 4.4 出题：生成、校验、发布

每道题提交时依次检查：引用合法；题目只用到本活动及已学的知识点；题干与答案一致；再由独立的审校 Agent 读取引用原文后给出结论，审校不通过则退回修改。编程题的参考解在 Judge0 里跑全部测试用例，不通过不能发布。隐藏用例不返回前端。

### 4.5 判分与提示

选择题、填空题在本地比对；编程题提交到 Judge0，异步轮询结果，判题服务故障不算答错。提示分 4 级，第 4 级是完整解析，需要二次确认。

### 4.6 掌握判定

对每个知识点收集独立作答证据：同一题（题型、题干、答案相同）只计第一次；看过第 4 级提示后的作答不计。满足以下条件才算掌握：

- 至少 3 道不同的题；
- 最近 5 题正确率不低于 80%；
- 最近一题答对。

课程设为「掌握后才能继续」时，未达标会自动安排补练。

### 4.7 学习助教

助教用 Vercel AI SDK 流式输出，工具只有本课程资料的 `search_sources` 与 `read_source`，回答以「〔来源ID·第N段〕」标出处，前端渲染为可点击的朱批出处。当前题组还有未完成的题时，提供给助教的上下文不含答案与解析，并要求它不直接给答案。对话只存在浏览器 localStorage。

## 5. 核心功能实现

- **教材解析**：七种格式统一成章节树。MOBI/AZW3 用内置纯 JS 解析（PalmDOC 解压），带越界检查、64 MiB 解压上限，识别 DRM 并提示转换。PDF 无文字层时明确报错。
- **断点续跑**：Agent 会话与已验收产物持久化在 `vl_agent_states`。任务中断后继续，已通过的知识点、小节、题目不重复生成。
- **生成过程可视化**：轨迹接口只返回白名单字段（工具名、读取区间、搜索词、引用段号、题号、错误类别），不含提示词与正文。「书带」把读过的段落画成灰色，把采用的出处画成朱红细线。
- **三种学习模式**：理论、练习、刷题共享同一份学习记录，可以随时切换。
- **笔记**：按知识点保存，带修订号防覆盖；导出为带 frontmatter 的 Markdown；本地模式可写入本机 Obsidian vault（`<vault>/智学伴/<课程>/<知识点>.md`）。

## 6. 安全设计

- **访问控制**：本地模式只监听 127.0.0.1:3101，终端口令登录；线上模式用访问码登录，每个浏览器一个空间，按 IP 限制登录频率，30 天未访问的空间自动删除。
- **同源校验**：写操作校验 Origin 与 Host，拒绝跨站请求。
- **模型 Key**：线上模式下 Key 存在浏览器 localStorage，需要模型的请求经 `X-VL-Model` 头传给服务器，服务器只放进程内存，任务结束即删。错误信息中回显的 Key 会被替换为「[已隐藏]」。`scripts/check-key-leak.ts` 对数据库、WAL、上传目录做字节级搜索，测试里跑完整流程后命中数为 0。
- **防 SSRF**：联网资料与线上模式的模型地址只允许公网地址，DNS 解析结果固定到已检查的地址，重定向逐跳重新校验，模型请求禁止重定向。
- **页面**：严格 CSP（nonce + strict-dynamic）、`frame-ancestors 'none'`、nosniff；Markdown 渲染不执行 HTML。
- **代码执行**：学生代码只在 Judge0 中运行（关闭网络），主机上不执行。

## 7. 测试与部署

- Vitest：64 个文件、404 项，覆盖解析、课程编译、证据与掌握、空间隔离、Key 不落盘、SSE、轨迹脱敏、助教防泄题、SSRF。
- Playwright：47 项端到端测试，接口用模拟数据；axe 无障碍检查 12 个页面加登录页与手机宽度，严重违规为 0。
- 部署：国内云服务器 + Nginx（HTTPS、SSE 关闭缓冲）+ systemd 加固单元 + Judge0 1.13.1（只绑定本机端口，关闭网络）。步骤见 `deploy/README.md`。

## 8. 创新点

1. **段落级出处贯穿全程**：从课程方案、课件到题目、助教回答，每个结论都能点回原书那一段。
2. **生成过程透明**：执行记录与书带展示 Agent 读了哪里、改了什么，不伪造模型的思考过程。
3. **工具校验驱动的 Agent**：模型提交的内容先被校验，失败原因反馈给模型修正，通过的产物才落库。
4. **「学过」与「学会」分开**：掌握靠不同题的独立作答证据判定，提示与解析的使用会影响证据。
