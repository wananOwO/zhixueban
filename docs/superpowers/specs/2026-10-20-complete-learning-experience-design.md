## 1. 为什么重新融合

已提交的 verified-learning 总设计第 14 节，把阶段 2 定义为编课、先修闭包、来源检查和确认页面，把测评/执行/证据放在阶段 3。用户指出原先的产品“第二轮”是补齐教材库、继续学习/回看、建课草稿与防重复体验，希望两者融合。

两套划分不相互替代。本轮以“导入教材—保存草稿—生成/确认课程—实际学习/编程练习—退出后继续—回看记录”为验收主线，把来源、版本、幂等与隔离执行等能力放进对应环节，不能交付一个只能确认课程、无法开始学习的页面。

本轮明确包含部分原第三阶段能力：用户已选择编程自动运行与判分一起完成，不能按上一份计划把所有测评功能后置。原来 4—7 小时的编课估计不再适用；后续以拆分后的实施任务重新评估，不先承诺完整交付时间。

## 2. 已确认的范围与执行边界

### 用户已经确认

| 项目 | 确认内容 |
|---|---|
| 继续与回看 | 再次打开课程回到上次学习位置；自由查看历史课件、已做题目和答案解析；回看不推进当前进度、不重复记分 |
| 建课草稿 | 输入自动保存，退出/刷新后恢复；生成结果和人工调整保留；重新打开不重复调用 AI；同教材支持不同目标的多个草稿；显式确认才成为正式课程 |
| 防误重复 | 连点、刷新、网络重试不能误建多份；正常创建不同目标的课程仍允许 |
| 教材整理 | 归档与彻底删除都做；彻底删除前列明关联影响并二次确认；有课程引用时不能直接删除 |
| 编程与运行环境 | 本轮加入编程自动判题及其隔离、题目验证、故障反馈；本机使用、最小访问口令、不建设公网账号、暂不合并主线 |

用户已最终确认本融合设计，并补充 C 语言支持。确认设计不构成删除现有数据、迁移真实库、启动长期服务或直接执行尚未确认的实施计划的授权。

### 经本次确认的实现边界

| 选择 | 原因与限制 |
|---|---|
| 编程语言支持 Python 3、JavaScript、C | 用户在最终确认时明确增加 C；C 的编译与运行都在隔离环境内，编译错误单独反馈；本轮不扩展 C++ 等其他语言 |
| 提示词复用、笔记入口、画像筛选一起纳入简版 | 都直接服务本轮使用路径，不扩张为模板市场、跨设备笔记同步或复杂报表 |
| 不自动升级/重算旧课程和成绩 | 旧数据缺少增强证据；保留可继续和可回看的兼容路径，新数据不能伪装成过去已有 |
| 课程与教材删除不做一键级联 | 防止误删历史引用；归档不能当作引用已解除。已被课程/历史引用的教材本轮只允许归档 |
| 教学页面先复用现有风格 | 不做全站重设计；必要入口/导航补齐，优先保证真实流程可用 |

## 3. 交付范围

### 3.1 教材库：找得到、看得懂、能继续使用

- 支持书名搜索、可用/处理失败/已归档等状态查看、章节目录、解析后的原文预览和课程关联入口。原文预览以解析文本为准，不承诺保留 PDF 原排版。
- 从教材进入相关草稿和课程，或创建不同目标的新课程；不要求反复上传同一本书。
- 导入提供明确的处理状态与失败原因；失败重试不能留下重复教材、索引或错误的“已完成”记录。
- 同一文件再次上传时，按服务端文件内容身份提示使用已有教材；同名但不同内容不直接判为重复，也不自动覆盖旧版。
- 沿用已支持的文件格式；本轮不新增扫描件 OCR 工程。解析失败应可理解地提示，不能伪造成功。

**归档：** 隐藏于默认列表，可恢复；不删除文件/引用，不阻碍旧课回看。新建课程默认不选择已归档教材，恢复后可再用。

**彻底删除：**

1. 服务端生成影响清单：原文件、解析内容、检索索引、来源快照、草稿/课程及历史引用。
2. 没有关联使用的教材可在二次确认后删除；有使用中的任务或草稿先处理草稿/取消任务，有课程/学习记录引用则阻止删除并提供归档入口。
3. 本轮不提供“连课程、笔记和成绩一起清空”的级联删除；用户选择归档后，引用保护仍然存在。此限制须在界面明确说明。
4. 真正执行前再次检查关联，避免预览后出现新课程；删除范围限应用拥有的数据目录和对应记录，不接受客户端文件路径。
5. 文件清理失败不能显示全部删除成功。实现计划应安排可重试清理记录和一致性测试；无关教材、备份及用户电脑上的原始文件不受影响。

### 3.2 建课草稿：自动保存不等于自动建课

- 选择教材、目标、教学要求、已有基础、学科/模板、题量、难度和补充策略时自动保存到本机应用数据；不能只靠内存。保存状态须显示“保存中/已保存/保存失败”。
- 刷新、关浏览器、重启应用后可继续；保存失败时不谎报已保存，离开前提示尚未保存的更改。
- 每个草稿有独立身份；同一教材可建“基础语法”“算法竞赛”等多个草稿。默认提供继续已有草稿，也保留明确的新建入口。
- 草稿输入与生成后的大纲/编辑分别保存；自动保存输入不意味着每按一次键就生成正式课程版本。
- 生成时锁定所用输入版本；用户期间修改输入，旧生成结果不得覆盖新编辑，须说明结果对应旧输入。
- 两标签页修改发生冲突时提示并保留本地编辑，不能无提示覆盖。
- 未生成或未确认的内容都不进入正式课程学习列表；最终确认才创建或激活课程。

**防重复规则：** 请求重试恢复同一个任务/结果；双击确认只得到一个正式课程；重新打开草稿不调用模型；“以此为模板再建一门”是明确的新请求，不按内容相似强制合并。

### 3.3 编课：技术校验服务于用户确认

- 以知识点而非整章裁剪：不学游戏项目，也保留算法需要的函数等基础。
- 计算未被已有基础满足的必要先修，检查循环、引用缺失和错误顺序，展示保留/跳过/重排/补充理由。
- 引用能够打开对应教材版本、章节与段落。服务端核对来源、摘录和内容版本；不能把模型自报 ID 当成真实来源，也不能把来源存在当成内容正确的证明。
- 教材不足时列出缺口。用户可补充资料、调整目标、确认已有基础或修订有争议的先修关系；未解决的阻断问题不能直接确认。
- 补充资料先限已导入的本机教材/资料，不提前建设任意网址抓取。
- 允许人工调整知识点与顺序；保存后重新检查。已有正式课程改目标/大纲/教学约定要生成新版本，不重写旧课件或成绩。
- 保留数字/命名三模式映射，默认题量 3/10/10、上限 50，以及现有已批准学习约定。

### 3.4 学习工作台：继续和回看分开

**继续学习：**

- 打开课程默认进入其当前学习活动和已保存位置。记录读到的内容位置与学习活动完成状态分开，不能把“课件生成完成”当“用户读完”。
- 阅读由用户明确完成；题目按实际作答状态恢复。未提交的输入可保存，但不计为作答或成绩。
- 已生成课件、已发布题目、已提交答案与反馈持久化；刷新不重生成，重复提交不多记一次成绩。
- 理论、边学边练、刷题三种模式使用已批准的第一阶段调度规则；切换保留课程版本和历史，进行中活动须完成或明确放弃。
- 刷题基础来自明确自报或实际诊断，不能把“能打开知识点”当作“已学过”。

**回看：**

- 大纲/历史列表可打开旧课件和已做题目；显示当时题面、本人答案、判定、已保存解析/提示使用记录和课程版本。
- 回看是读取，不启动出题/重新判分，不更新当前课程完成状态，不增加作答量、掌握证据或热力图。
- 查看历史页面不覆盖“继续学习”的活动位置；离开回看可一键回到当前活动。
- 未答题不能借历史接口提前读取答案或隐藏测试。重新练习必须是明确的新活动，不把历史回看伪装成一次作答。
- 老记录没有保存的解析/位置显示“旧记录未保存”，不捏造历史；如提供补充讲解，须由用户明确触发并标为新生成。

课件先支持安全 Markdown、公式、代码和来源预览，不运行教材或模型输出的 HTML/MDX/脚本。多媒体/外部连接不作为本轮完成前提。

### 3.5 测评与编程自动判题

**题目发布：**

- 分离题目生成、校验与学生作答判分。校验结构、所属课程版本、允许知识范围、来源、答案及参考解一致性；校验失败不发布。
- 不仅信任模型自报的知识点标签；模型审校的结论、确定性检查、执行结果分别记录，缺少审校结果不能默认通过。
- 选择题/受限填空按明确规则比较；开放回答只作辅助反馈，不单独成为已验证掌握。
- 编程题参考解必须先通过有效测试；空测试、无效测试、参考解失败均不能发布。固定样例覆盖正常、边界与错误路径，不能只验一个示例。

**执行与反馈：**

- 新代码执行统一经过独立 JudgePort。采用受控的隔离判题服务，Python 3、JavaScript、C 均不回退为网站进程里的 node:vm 或宿主命令执行。C 的编译过程同样受资源/网络/文件隔离限制，不在宿主编译。
- 请求只传受控语言、题目/用例版本和代码；用户不能指定容器镜像、宿主路径、命令或网络权限。
- 限制时间、内存、进程/文件资源和输出量，禁用学生程序网络，不挂载个人文件、模型密钥或 Docker socket。题目/答案/测试本身也视为不可信内容。
- 显示通过、错误答案、编译错误（包括 C 编译失败）、运行错误、超时、资源超限、判题服务故障的区别。服务故障不算答错，不推动完成/掌握，允许明确重试。
- 保存每次提交的输入、题目版本、执行结果与可展示反馈；重复网络请求不重复执行/记分。隐藏测试与标准答案不出现在学生未作答 DTO 或错误堆栈里。

**环境验收：** 已确认本机存在 Docker CLI，但尚未确认引擎运行、判题服务、镜像与资源策略。不能据此宣称安全运行已就绪。部署配置先审查、只绑定回环地址；需管理员操作或长期服务由用户执行。没有真实隔离服务测试时，只能交付“适配器已测试”，不能宣布编程自动判题完整验收。

### 3.6 学习证据与画像筛选

- 继续区分阅读完成、练习完成、自报基础、诊断和已验证掌握；画像先支持按课程筛选，不再默认混用最近一本教材的知识图和全库答题量。
- 复用原已批准规则：每知识点至少 3 道不同的已验证题，最近最多 5 道有效独立作答正确率达到 80%，且最近一题独立答对，才符合 verified。
- 看完整解析后的重做不能充当独立掌握证据；旧引擎分数、阅读和声明不自动转 verified。服务故障不进入有效正确率。
- mastery 进阶策略由真实证据解除门槛，不能用完成按钮绕过；默认 completed 保持做完可继续。
- 热力图只统计真实学习/作答事件，回看和请求重试不加次数。不同课程/版本按明确规则归属，课程历史不能被新版本覆盖。
- 本轮展示基本复习状态和到期提示，不建设独立的复杂复习调度中心；原规则“验证后 7 天待复习”不等于判定用户已经遗忘。

### 3.7 提示词与笔记：最小但可使用

**提示词复用：** 建课时选择内置/已保存模板，允许将自己的教学要求保存为模板并再次选择。课程保存实际采用的模板内容快照；修改模板不悄悄改变已有课程。模板只影响讲解偏好，不能关闭验证、权限或数据保护。不做公开市场。

**笔记入口：** 在课程/知识点上下文打开和编辑笔记，显示所属课程、知识点与保存状态；支持课程内浏览和 Markdown 导出。同教材不同课程不混用笔记；旧笔记按能确认的归属展示，归属不明确不能自动套到每门课程。不做 Obsidian 实时双向同步。

## 4. 历史兼容与技术执行原则

- 第一阶段核心不重做。既有课程继续可用，旧记录原样保留；增强课程使用版本化会话/证据。两类记录在统一入口明确标记来源，不能混为同一套已验证成绩。
- 旧课程继续/回看的必要修复按兼容补丁隔离：读取已存课件与历史、区分生成和阅读完成、防止回看触发生成/记分。旧数据缺少阅读完成记录时明确提示，不能凭课件存在伪造学习进度。
- 新课程必须能实际进入本轮工作台；不能最后仅显示“工作台尚未接入”，也不能偷偷送入旧评分引擎冒充增强闭环。
- 代码、文件、数据库、测试均在增强 worktree；不复制 main 的未提交改动，不因主线有笔记/设置页便假设增强线已具备。
- 数据增量迁移、备份、事务、scope 和幂等保持第一阶段约束。真实迁移由用户执行，测试用隔离临时库。
- UI 沿用设计系统，窄屏可用、键盘可操作、有可见焦点与文本替代；先补全入口和状态，不改全站视觉风格。
- 本地访问口令与服务端身份检查用于新能力；旧未统一鉴权接口仍使应用只适合回环开发，不宣传公网可用。

## 5. 不做与不承诺

- 不自动同步主线、部署公网、多账号/学校管理或跨设备同步。
- 不做新文件格式工程、扫描件 OCR、视频生成、语音、任意 MCP/外部库连接和复杂笔记同步。
- 不在主机直接运行学习代码，不用没有依据的“安全沙箱”标签，不承诺程序题或模型语义零错误。
- 不静默覆盖历史课程、来源、作答，不把旧分数转换成已验证证据；不提供课程/教材/笔记一键级联清空。
- 不把 mock 测试视为真实模型或判题运行效果；不把“已加入计划”描述为“已实现”。

## 6. 按可用体验拆分交付

| 顺序 | 可独立验收的结果 |
|---|---|
| A | 教材库查询、原文预览、重复上传提示、归档及受保护删除 |
| B | 可恢复建课草稿、提示词复用、生成恢复、防重复确认与来源/先修编课 |
| C | 学习工作台、独立阅读完成、继续/回看、课件和客观题记录、笔记入口 |
| D | 题目验证、隔离代码执行、判题故障恢复、幂等作答、真实掌握证据 |
| E | 画像筛选、旧记录兼容验收、断网/重启/跨课程测试与完整浏览器流程 |

这些是同一轮的内部交付次序，不是把用户已要求的 D 项偷偷后置到另一轮。C 中暂不可执行的代码题明确等待 D，不通过旧执行器绕过；只有 A—E 及约定的真实环境验收完成，才称本轮完成。

## 7. 可观察的最终验收

1. 两本教材和同教材两门课程互不混用；重复上传有提示；归档可恢复；有关联的删除被阻止，无关联删除不会触及其他数据。
2. 草稿填写/生成/调整后分别刷新、退出、重启都可恢复；断网重试和双击确认只有一个预期任务/课程；明确新建不同目标仍可创建。
3. 新课程确认后可实际学习；关闭重开回到未完成位置；回看旧课件/题目/解析不生成新内容、不改变进度/分数/热力图。
