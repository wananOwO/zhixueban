# 工具驱动的学习 Agent 重构方案

用户已确认：按学习活动生成，允许联网补充公开资料，授权一次真实课件验收最多30次模型请求。核心代码已接入；真实课件验收被供应商content_filter拒绝阻塞，不能标全部完成。

## 目标与现状

用户要求真正的 Agent：模型自主选择工具、多轮读取/生成/修正，只有工具验收通过才完成课程方案、课件或题组。现有 `generateText + Output.object` 的单次调用不是该执行机制，不能通过外层重复调用冒充 Agent。

不重新加入字数门槛或60秒固定中止；不为格式纠错固定三次就失败。用户取消、认证/额度阻塞等客观条件不能伪报成功。课程确认、读完、成绩和掌握证据语义保持，Agent不能代学生读完或作答。

## 框架选择

优先直接依赖固定版本 `@earendil-works/pi-agent-core@1.4.0` 和匹配 `pi-ai`，而非搬入coding CLI。MIT允许复用；保留依赖许可，如复制/适配源文件则记录上游提交和版权。

当前查阅上游 `main@74f46864025c68504cd10c89eeb626b7e3d64cea`。关键采用Agent工具参数验证、工具错误回传、自动续轮、finishTurn完成门槛、terminate验收终止。参数被输出长度截断时不执行工具，向Agent返回需要拆分/重提。

仅加载自有教学工具，无终端、任意文件访问、学生代码宿主执行等通用编码工具。服务端使用现有设置中的供应商/地址/模型/密钥；不使用Pi个人账户配置、环境中的无关凭据或项目级skills。

## 执行循环

1. 用户触发生成，任务绑定不可变目标、来源版本、活动范围；创建或恢复Agent会话。
2. Agent自主读取目录、搜索已选资料、分页获取原文；完整教材都可访问，不将46万字硬塞进每轮请求，不悄悄截掉后文。
3. Agent通过结构化工具提交知识点/课件段落/题目。工具先做结构和业务验证，返回明确问题位置、违反规则和可重试修正建议。
4. 工具结果加入同一会话；Agent继续查资料、修改相应单元、重新提交。不使用字段猜测映射或去掉验证条件来凑合通过。
5. Agent调用最终验收工具，工具核对阶段清单、所有单元和引用/题量/题目审校；通过才原子发布产物和任务成功。普通助手文字不作为产物，也不作为结束凭据。

### 工具职责

- `list_sources`、`search_sources`、`read_source`：真实来源目录/搜索/分页原文，限当前任务已授权来源。
- `submit_curriculum_point` / `submit_curriculum`：按知识点提交并核对先修关系、引用、目标覆盖，返回问题，缺口不得静默丢弃目标或虚构引用。
- `submit_lesson_section`：分节保存讲解、示例、总结与来源；可替换已有节而非重复追加。
- `submit_question`、`review_question`：题量、目标范围、唯一答案、样例和审校；代码参考解只能由隔离Judge0验收。
- `finish_generation`：校验全部成果；未通过返回错误继续Agent循环，通过后一次性发布。`report_blocker`记录真实不可解决条件，不标成功。

上述名称为设计接口，实施计划会固定参数。课程、课件、题组运行时只挂载该阶段必需工具。验证依赖当前确定性来源/领域校验；结构正确不能宣称教学事实绝对正确。

## 状态、恢复与进度

新增增量会话/工具调用/产物存储，不把无限增长会话挤入现有4MiB单个checkpoint。每轮和每个工具结果落盘，记录供应商、模型、结束原因、耗时与Token用量；密钥不入会话。

写入工具使用稳定toolCallId和产物键保证幂等；领取任务的lease和心跳保留。关机后恢复已验收内容和工具记录，外部模型调用结果未知时明示，不假设未计费。跨事务提交和发布须复验任务/草稿版本防迟到结果覆盖。

已有API jobs/events扩充可读阶段：读取来源、编写第N节、校验发现问题、自动修正、验收通过。前端显示进度与停止按钮，不显示隐藏思考过程、题目隐藏答案/测试或完整私密会话。

取消必须传播AbortSignal到Agent和工具；取消/关闭后不再启动新的调用或发布。会话压缩/工具分页不等于删教材；已完成产物单独持久化，避免重传整书和无限上下文堆积。

## 自动纠错与停止语义

- 参数JSON错误、Schema错误、不存在工具、引用错误、缺失章节、题量不够、普通文本提前结束：反馈给Agent并继续处理，直到阶段验收通过。
- 输出被长度截断：不执行该批潜在残缺写工具，要求分段提交；不把任意8192输出预算当完成依据。
- 临时服务故障：保存原因并退避重试，不进行高速无间隔循环。
- 认证失败、余额不足、用户取消、真实来源不足：明确阻塞原因；不能通过Agent反复调用把客观障碍变成成功。
- 不沿用三次格式修复上限；连续完全相同操作且无进展应显示阻塞/允许用户停止，不假报完成。是否设置费用预算是调用授权问题，不是完成正确性的替代。

## 验收标准

1. 故障注入：首轮只说“完成”不得成功；错误参数/未知工具/错误引用/截断输入都回传，模型后续正确工具调用自动完成，无需用户重启。
2. 会话证据：至少一次自主读取来源、一次被工具拒绝、一次自动修正并验收成功的完整轨迹；断点恢复不重复提交已通过内容。
3. 完整课件：所要求的知识点对应讲解、示例和总结均存在，引用能定位；课件生成不自动标记阅读完成。
4. 安全与状态：取消停止后续调用，密钥不回显、未答题答案不泄露，代码不在宿主执行；异常请求不能越过scope/版本边界。
5. 真实端到端验收必须单独获调用授权；不能用模拟测试冒充用户供应商实际通过。外部永久故障报告阻塞，不承诺任何条件下无限调用必定成功。
