## 1. 目标与边界

提供通用教材学习框架，以 Python 语法和入门算法作为第一套完整验证场景。
系统围绕“目标与资料覆盖检查、先修约束排课、三模式教学、可检查的测评、
基于证据调整学习”形成闭环。演示价值来自可检查的结果，而非 Agent 数量。

复用主线已经实现的教材解析、基础存储、模型接入和应用外壳，不另建一套基础平台。
新模块通过端口和适配器调用这些能力，保留将模块逐个移植回主线的能力。

### 首版必须交付

1. 单主教材导入和解析预览；优先验证文本型 PDF、EPUB、Markdown、TXT。
2. 自定义目标、教学提示词、学习基础和测评设置；确认后生成课程版本。
3. 知识点先修关系、教材覆盖缺口、课程重排理由和人工调整。
4. 理论学习、边学边练、刷题学习；切换时保留历史和当前课程版本。
5. 题目质量检查、编程题执行判分、分层提示、可追溯学习证据。
6. 富文本课件、公式、代码、图片、视频卡片及预定义交互组件。
7. 真实学习记录驱动的进度、热力图、知识图谱和笔记。
8. 至少一个只读 MCP 工具接入；笔记导入检索和 Markdown 导出。
9. 隔离的评审体验会话、调用限额、可恢复任务与故障反馈。

### 扩展层

保留主线已有格式支持，但首版不为复杂扫描件、MOBI/AZW3 增加新解析工程。
Obsidian 实时双向同步、任意外部向量库直连、自生成长视频、语音克隆、
多租户学校管理和模型训练不进入首版验收。
用户可以导入外部知识库导出的资料；首版外部检索端口支持一个管理员配置的
只读 HTTP 检索连接器，不宣称兼容所有数据库协议。

## 3. 学习约定与课程版本

创建课程时保存以下设置：

| 字段 | 含义 |
|---|---|
| textbookId | 主教材标识 |
| goal | 希望达到的能力 |
| teachingPrompt | 如何讲解的自由文本 |
| priorKnowledge | 已有基础及其来源：用户声明或诊断 |
| includedTopics / excludedTopics | 关注与排除范围 |
| difficulty | easy、medium、hard |
| pointQuestionCount | 每知识点题数，默认 3 |
| chapterQuestionCount | 章末题数，默认 10 |
| finalQuestionCount | 综合题数量，默认 10 |
| progressionPolicy | 完成练习或达到掌握门槛，默认完成练习 |
| allowSupplementalSources | 是否允许补充教材外的来源，默认开启 |

题数是正整数，首版单次请求上限为 50；超出时由界面拆成多组，而非静默截断。
课程级设置可被章节设置覆盖，实际出题数量保存到测评记录。
不自动把“困难”解释为允许使用新的知识点。

学习提示词属于用户偏好，教材和外部资料属于数据；资料中的指令不拥有工具权限。
个性化提示词也不覆盖测评范围、隐私和内容执行约束。

课程从 draft 经用户确认进入 active。修改目标、知识点集合、先修关系或教学约定，
创建新版本；修改显示偏好和当前学习模式不创建版本。
历史课件、题目和作答始终引用其生成时的版本，不原地改写历史成绩。

## 4. 教材覆盖、知识图谱与编课

教材解析输出继续使用主线 `ChapterTree`。
增强层为文档建立内容版本、来源位置和知识点映射，不改变现有段落锚点结构。

编课步骤：

1. 提取学习目标和已有基础，形成用户可编辑的学习约定。
2. 抽取候选知识点及其教材证据；把关系区分为先修、相关和引用。
3. 验证知识点 ID、来源存在性和先修图无环性。
4. 选出目标知识点，计算未被已有基础覆盖的先修闭包。
5. 标识教材缺失的目标或先修知识；补充资料需有明确来源并由用户确认。
6. 按依赖关系排序，生成课程大纲和保留、跳过、重排、补充的理由。
7. 用户确认后保存课程版本，按需生成课件而非一次生成整本书。

排除“小游戏项目”不等于排除该章节承载的函数等基础知识。
用户删除或重排节点后重新验证先修关系；未解决的依赖缺口保持在草稿状态。
图谱布局不改变教学顺序；语义相似边不自动成为先修边。

## 5. 三种学习模式与共享状态

对外保留主线数字模式：1 理论、2 边学边练、3 刷题。
增强层内部使用有名字的枚举，由适配器进行一对一转换。

| 模式 | 活动序列 |
|---|---|
| theory | 章节内知识点讲解完成后进行章测 |
| practice | 每知识点讲解、练习，再进入下一知识点；章末进行章测 |
| drill | 逐知识点练习，最后进行综合测评；不自动插入理论讲解 |

不同状态分别记录：可访问、已展示、练习完成、具有掌握证据、需复习。
观看内容不直接形成掌握证据；解锁也不等于已学习。

“允许用于解题的知识”由已讲授知识、通过诊断的已有基础和明确自报的已有基础构成，
三类来源均可追踪。自报基础不自动转成已验证掌握。
刷题前未建立基础范围时，先确认自报范围或进入独立标记的诊断活动。
诊断不冒充已学内容练习，也不在未说明的情况下改变课程进度。

切换模式时保留当前版本、已完成活动、作答、笔记和来源。
进行中的题目完成或由用户明确放弃后切换；只重新安排未开始的活动。
错误答案触发反馈与补练建议；是否强制达标由 progressionPolicy 决定。
模型判分不确定或判题服务故障时，不计为学生答错。

## 6. 题目生成、验证与判分

每题保存目标知识、实际依赖、来源引用、参考解法、答案、评分规则、
生成模型和提示词版本、验证结果以及可使用的课程版本。

发布流程：

1. 从课程版本和学习状态得到允许知识范围。
2. 生成候选题、参考解法和评分规则。
3. 校验结构、引用、知识点存在性和先修范围。
4. 分析参考解法实际使用的知识，而不只接受模型声明的 sourceKPIds。
5. 对支持的题型执行确定性检查；编程题执行参考解与测试用例。
6. 独立复核题干、参考解和范围的一致性；未通过则不发布，重试最多 2 次。
7. 保存验证记录后入库，向学生只发送去除答案和隐藏用例的展示对象。

确定性检查仍不构成对任意开放题的形式化证明。验证记录区分结构检查、
执行检查和语义复核，界面不使用“保证零错误”等描述。
主观题的模型评分标记为 advisory，只用于反馈；不单独推动 verified 状态。

编程题通过独立 JudgePort 执行。执行器运行在隔离环境，限制运行时间、
内存和输出大小，禁用学生代码的网络和宿主文件访问，不挂载模型密钥。
参考答案先通过用例和基本边界检查；执行器不可用时不发布新的编程测评，
已有题保留为等待执行状态，普通阅读和客观题学习继续可用。

分层提示包括概念、思路、局部步骤和完整解析。
记录实际使用的提示等级；查看完整答案后的重做不算一次独立掌握证据。
对用户不服判的答案支持标记和重新评价，保留原始记录及修订原因。

## 7. 掌握证据与复习

首版采用透明规则而非未经校准的概率模型：

- 每知识点至少 3 道不同的已验证题，才允许进入规则判定。
- 最近最多 5 道有效题的独立作答正确率达到 80%，且最近一题独立答对，
  才标记为 verified。
- 使用完整解析的作答不参与独立正确率统计；一般提示单独展示，不隐藏。
- 客观题和执行验证的编程题可以形成确定性作答证据。
- 主观题 advisory 分数展示为反馈，不混入上述正确率。
- 用户自报掌握以 declared 单独呈现，不伪装为测评结果。
- verified 后 7 天进入待复习队列；到期不自动判定知识已经遗忘。
- 复习中的有效错误将状态调整为 needs_review，保留过去证据。

这些阈值是首版产品规则，不宣称具备经过实验校准的心理测量意义。
规则版本随证据记录保存；调整规则后按记录重算，不修改原始作答。
进度图分别展示完成度、有效作答、掌握证据和复习状态。

## 8. 资料与可信课件

资料分为主教材、个人补充资料、外部检索来源和模型生成内容。
引用记录 sourceId、sourceRevision、位置锚点、摘录及内容哈希。
外部资料额外记录 URL、获取时间和适用技术版本。
来源回查由服务端验证；模型输出的引用 ID 本身不构成来源证据。

首版复用 sqlite-vec，增加检索范围适配层。
必须通过多教材、不同知识范围和不同 embedding 配置的隔离测试。
模型或向量维度改变时建立新索引，不混合旧向量。
聊天模型与 embedding 模型拥有独立配置，旧环境变量通过适配器兼容。

课件使用可验证的内容块：markdown、math、code、image、video、
quiz、interactive。interactive 仅引用开发者实现的组件 ID 和校验后的参数。
富文本进行清洗；不把教材、检索结果或模型输出当作可执行 MDX/JSX。
来源缺失或相互冲突的事实显示待核实状态，允许重新检索与更换资料。

媒体记录来源与使用说明，优先使用有权展示的教材素材、原创图示和可嵌入资源。
视频加载失败时保留文字说明与来源；媒体不是学习流程的单点依赖。
至少实现一个有教学意义的图片理解或交互演示场景，不以插入装饰图片冒充效果。

## 9. Agent 工作流与任务恢复

一个受控工作流负责状态转换；规划、检索、教学、出题、审校是职责边界，
不是必须同时运行的五个独立对话 Agent。

耗时操作均保存为任务：queued、running、waiting_user、succeeded、
failed、cancelled。任务有稳定 ID、请求幂等键、阶段结果、尝试次数、
预算和错误分类。阶段结果持久化后再发布事件。

关闭浏览器不删除任务；重连通过任务状态和事件游标恢复显示。
同一幂等键不重复创建课程或题目；上游模型调用结果不确定时记录独立尝试，
不承诺第三方计费天然幂等。
学习页面显示阶段、工具、来源和简短结果，不展示或伪造模型内部推理。

## 10. 外部连接

### MCP

首版仅启用管理员预配置的搜索和文档读取工具。
公网体验者不配置任意 stdio 命令、服务器地址或文件路径。
工具权限在服务端执行，不把 read-only 描述视为权限保障。
连接器限制目标地址、重定向、响应大小、超时和调用次数；
远程结果只作为资料，不获得新增工具权限。

### Obsidian

首版支持选定笔记文件/导出包导入、检索、应用内来源预览、Markdown 导出。
本地实例可配置选定 Vault 目录的只读连接；VPS 不将用户电脑路径当成可访问路径。
完整实时同步不属于首版，删除导入副本、撤销连接和清除索引属于首版。
Obsidian 链接图仅作为资料关系来源，教学先修图独立维护。

### 外部 RAG

定义统一检索请求和返回证据格式，首版实现一个受信任只读 HTTP 连接器。
每条返回证据必须标识来源和内容版本；缺少必要元数据时作为非引用性参考。
连接器不默认上传整本教材或整个 Vault。

## 11. 页面与部署

页面包括资料库、课程设计、学习工作台、复习中心和学习画像。
学习页沿用主线设计系统：大纲导航、主要学习内容和可折叠的证据/笔记侧栏。
窄屏切换为单列，保留键盘操作、可见焦点、文本替代和 reduced-motion 支持。
热力图来自有效活动事件，前台停留时长与真实答题分开统计。

本地部署与 VPS 使用同一应用代码，但连接器能力随部署模式显式配置。
管理员和评审体验分离；评审会话具有独立 scopeId、独立学习状态和调用预算。
公共演示不使用个人教材或私人 Vault；登录/访问控制落实前只在回环地址开发。
密钥只由服务端管理，不进入前端响应、导出包、提示词快照或工具日志。

## 13. 验收

首个纵向交付不以覆盖所有格式为完成标准，而以下列场景为标准：

1. 同一 Python 教材为语法/算法目标生成不同于游戏项目目标的大纲。
2. 跳过游戏项目时保留函数等必要基础，教材缺少算法内容时展示补充缺口。
3. 题目虚报知识点标签、使用未学构造或引用不存在来源时被阻止发布。
4. 参考代码运行失败、用例不成立或学生代码边界错误时有可检查反馈。
5. 三种模式切换保留已完成活动与作答，刷题基础范围明确。
6. 刷新、断网、重复请求和进程重启不重复创建已完成的课程/题目。
7. 两本教材和两个体验会话之间的检索、答题、笔记互不混用。
8. 禁用 MCP、媒体失败或执行器故障时进入对应降级状态，不误判学生。
9. Markdown/媒体渲染不执行输入脚本；非管理员不修改工具或模型配置。
10. 旧教材接口的契约测试继续通过，增量迁移不破坏旧字段读取。

测试分为纯逻辑、数据库/迁移、HTTP/权限、浏览器流程和固定样例的模型评测。
模型评测记录实际运行成本、检索命中、引用正确性和范围违规；
结果不从 mock 测试推断，不发布未经实际测量的效果数字。

## 14. 分阶段交付

1. 契约、课程版本与学习状态核心，独立单测和兼容测试。
2. 目标编课、先修闭包、来源检查和课程确认页面。
3. 三模式、题库、验证器、JudgePort、证据与复习。
4. 可信课件、MCP/笔记连接、可视化和受控评审体验。
5. 故障恢复、模型评测、演示材料与可复现交付。

每阶段单独写实现计划并交付可测试切片，不一次性并行建设所有子系统。
第一阶段优先在新增目录内交付，不接管主线正在实现的 agent 文件。

- 保留用户的三模式、默认题量、自由提示词、多媒体和可选连接需求。
- 编程验证与主观反馈区分，掌握证据与阅读进度区分。
- 本地 Vault 与远程服务器文件系统区分。
- 新增表、路由、代码目录和提交边界明确；共同代码仅通过独立兼容补丁调整。
- 代码实现、公共接口切换和生产部署尚未发生。

方向确认后，先由用户复核本书面规格，再使用 writing-plans 编写第一阶段实施计划。
