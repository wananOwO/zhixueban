# 智学伴前端重做与线上站设计

日期：2026-10-27 · 分支：`feat/verified-learning` · 状态：待用户审批

## 1. 为什么做

智学伴是一个 AI 驱动的自主学习平台：用户导入教材、写下学习目标，Agent 读教材后生成课程方案、课件和题组，学生学完要用不同的题证明掌握。后端 demo 已完成，第一版前端功能可用但过于简陋，不足以参赛。

本次要做到：

- 评委看 3 分钟演示视频就能明白这个产品和普通“AI 生成课程”的区别：**每句话都有出处，掌握要有证据，AI 的工作过程看得见**。
- 评委打开线上站，输入访问码和自己的模型 Key，就能完整走一遍：上传教材 → 写目标 → 看 Agent 生成 → 学习 → 答题 → 看掌握进度。
- 本地自用版照常可用。

用户要求按最高质量做，不考虑工期。

## 2. 目标、非目标、反目标

**目标**

1. 11 个页面全部重新设计、重新编写，不在第一版代码上修改。
2. AI 流式交互：Agent 生成过程实时推送（SSE），学习页加 AI 助教对话（Vercel AI SDK 流式输出，回答带教材出处）。
3. 完整在线版：每个浏览器一个独立数据空间，保留访问码，用户的模型 Key 只存在浏览器和服务器内存里。
4. 桌面 1440、平板 768、手机 390 三种宽度各自成立。
5. 无障碍：键盘可操作全部功能，焦点可见，屏幕阅读器能读懂进度和结果。

**非目标**

- 不改后端的教学语义：掌握标准、先修校验、引用回查、幂等、判题隔离保持原样。
- 不做账号体系、找回密码、多人协作。
- 不做独立的演示版逻辑：线上站与本地版是同一套代码，靠环境变量切换模式。
- 不做语音交互（用户选了“界面重做 + AI 流式交互”档）。

**反目标（技术上能用也算失败）**

- 界面看起来像套模板的 AI 生成页：渐变、发光、毛玻璃、图标方块卡片、emoji。
- 页面有大片无用空白（用户对样张 A 的明确意见）。
- 用户的模型 Key 被写进数据库、日志、文件或错误信息。
- 访问者之间能看到或删除对方的数据。
- 为了“看起来在动”伪造进度：所有进度、计数、引用都来自真实数据。

## 4. 做法比较

### 4.1 视觉风格（已选）

做了三张真实数据样张（`.superpowers/brainstorm/frontend-redesign/`）：

| 方案 | 特点 | 取舍 |
|---|---|---|
| A 朱批本 | 白纸宋体，红笔旁注出处，红勾红叉批改 | 最好读、出处卖点最直观；用户认为留白太多 |
| B 荧光笔夜读 | 纯黑底，荧光绿标引用，“书带”显示 Agent 读了哪里 | 最适合拍视频；长时间阅读累 |
| C 先修路线图 | 青灰框白纸面，路线图 + 掌握证据圆点 | 最清楚；最像普通后台 |

用户选择：**A 的视觉 + B 的铺满密度 + C 的路线图**。B 的“书带”作为课件生成页的组件保留（真实数据支持，见 6.4）。

### 4.2 线上站的 Key 保存（已选方案 1）

课程生成在服务器后台跑 4–45 分钟（实测一次课程大纲 44 分钟、98 次模型请求），期间服务器必须拿得到 Key。

| 方案 | 做法 | 取舍 |
|---|---|---|
| **1 服务器内存（已选）** | 浏览器存 Key，发起生成时随请求带上；服务器只放进程内存，不写库不写日志 | 服务器重启后任务暂停，提示重填 Key 再继续，已完成部分不丢 |
| 2 全程在浏览器跑 | Agent 移到浏览器 | 另写一套逻辑；生成期间不能关页面；多数供应商不允许浏览器跨域直连 |
| 3 加密存库 | Key 加密后写数据库 | 重启可续跑；违背“不写入持久化文件” |

### 4.3 前端技术路线

| 方案 | 做法 | 取舍 |
|---|---|---|
| **1 在现有 Next 16 应用内重写（推荐）** | 保留 `src/lib`、API 路由与测试；删除 `src/app` 页面和 `src/components` 后重写 | 后端零迁移；比赛推荐首选栈 |
| 2 另起 Vite SPA | 前后端分离 | 失去 SSR 与路由约定；部署变复杂；无收益 |

## 6. 视觉系统

### 6.1 设计理念

**朱批本**：一本被认真批改过的教材。纸面白、墨色黑，只有一种红色——朱批。朱批只出现在三类地方：**出处**（这句话来自哪一段）、**批改**（这道题对还是错）、**当前位置**（你学到了哪里）。其他所有界面元素都是墨色和灰阶。

### 6.2 色彩

| 角色 | 值 | 用途 |
|---|---|---|
| 底色 | `#f3f3f1` | 页面背景 |
| 纸面 | `#ffffff` | 内容区 |
| 次级面 | `#ecebe8` | 分段控件、代码背景 |
| 墨 | `#1c1b1a` | 正文、主按钮 |
| 次文字 | `#5c5b57` | 说明（对白 7:1 以上） |
| 朱批 | `#b4182b` | 唯一色相（对白 6.6:1） |
| 朱批浅底 | `#fbefef` | 批改条背景 |
| 线 | `#e3e2de` | 表格、输入框边框 |

成功、警告不再用绿/黄色块：答对是红勾、答错是红叉，警告用墨色文字加图标。唯一例外是“判题服务故障”这类系统状态，用灰色。暗色主题不做（朱批本是纸面隐喻，暗色会稀释它）。

### 6.3 字体与字号

- 课件正文、页面标题：Noto Serif SC。正文 17.5px / 行高 1.85，每行 30–38 个汉字。
- 界面文字（导航、按钮、表单、数据）：Noto Sans SC 14px。
- 代码：JetBrains Mono 14px。
- 字号阶梯：12 / 14 / 17.5 / 23 / 30。页面标题 30px（手机 22px）。数字一律等宽数字（`tabular-nums`）。

### 6.4 标志性元素

1. **朱批旁注**：课件每个被引用的句子下有一条细红下划线，句子所在行的右侧旁注栏写着“教材 · 第 761 段”和原句。点旁注打开原文侧栏，滚到那一段并高亮。
2. **批改标记**：手写感的红勾、红叉（SVG 笔画）。看过完整解析的题打灰叉，表示不计入证据。
3. **先修路线图**：课程页主体。知识点按先修层级从左到右排开，连线是先修关系；每个节点显示最近 5 题的批改标记（红勾/红叉/空圈，对应掌握标准里的“最近 5 题”）。当前节点朱批描边。鼠标悬停或键盘聚焦一个节点时，高亮它的整条先修链。节点是可点击的按钮（进入该知识点）。手机上改为按层级分组的列表（同一份数据）。
4. **书带**：一条代表整本教材（例如 4,049 段）的横条，朱批细线标出 Agent 读过、引用过的位置；生成过程中实时增加。数据来源：Agent 的 `read_source` 调用参数（段落区间）和提交的引用段号，均已在 `vl_agent_states` 中记录。

### 6.5 布局与密度

- **铺满**：页面不设最大宽度，左右边距 24px（手机 16px）。界面尺寸全部用 rem，根字号在屏宽 1440→2560 之间从 16px 放大到 21px，宽屏整体等比放大而不是两侧留白。
- **课件正文例外**：正文栏保持 30–38 个汉字的行宽（约 640–720px），多出的宽度分给左栏目录和右栏旁注/助教，不拉长正文行。
- 顶栏 56px：标志、导航、模型 Key 状态。不设侧边导航栏。
- 学习页三栏：左栏课程目录，中间纸面，右栏旁注 / 助教 / 书带（按页面切换）。
- 课程主页：路线图占满整行，下方三栏（下一步 / 最近活动 / 资料来源），三栏等高、底部对齐。
- 列表类页面（教材库、课程、草稿）：表格式行列表，不用卡片墙。
- 间距基于 4px；圆角两档：纸面 4px、控件 6px。阴影只给浮层（菜单、对话框、提问栏）。

### 6.6 动效

只用于反馈和状态变化，全部尊重“减少动效”系统设置：

- 批改标记落笔动画（描边 300ms）。
- Agent 执行记录新增行淡入；书带新读的位置渐显。
- 助教回答逐字流式出现，带闪烁光标。
- 面板、对话框进出 150–200ms。

### 7.1 关键交互

- **引用回查**：点旁注 → 右侧打开原文侧栏，定位到段号并高亮；按 Esc 关闭。原文接口已支持分页读取。
- **助教对话**：学习页右栏或底部提问栏。选中一段文字可“就这段提问”。回答流式输出，末尾列出依据的段号（可点击回查）。回答只读当前课程已授权的资料。对话记录按会话存在浏览器 localStorage，刷新页面保留、清除浏览器数据即消失；服务器不保存。一次发送最近 20 轮。
- **生成过程**：发起生成后自动进入生成视图；SSE 断线自动重连并从断点续传；停止生成需二次确认；任务暂停（如服务器重启丢失 Key）时显示原因和“填写 Key 后继续”。
- **答题**：选择/填空/编程三类；编程题用 CodeMirror，显示公开样例；四级提示，第 4 级（完整解析）弹窗说明“看后这题不计入独立证据”；提交后批改标记落笔，显示解析。
- **自动保存**：草稿编辑沿用现有串行保存队列与修订号冲突处理；界面显示“已保存 / 保存中 / 冲突”。

### 7.2 状态

每个数据块都要有：加载中（与最终布局等大的灰条，不跳动）、空（保留框架 + 一句话 + 下一步按钮）、错误（块内一句话说明 + 重试，不整页报错）。

## 8. 新增后端能力

只增加前端需要、且后端语义已具备的能力。

### 8.1 任务事件流（SSE）

`GET /api/verified-learning/v1/jobs/{id}/stream?after={cursor}`：服务端每秒读取新事件推送（复用 `JobStore.events`），任务终态后关闭。支持 `Last-Event-ID` 续传。现有轮询接口保留作降级。

### 8.2 Agent 执行轨迹

`GET /jobs/{id}/trace`：从 `vl_agent_states.messages_json` 提取工具调用摘要——工具名、读取的来源与段落区间（`read_source` 的 offset/limit）、搜索词、提交的引用段号、校验错误摘要。已用真实数据核实：一次课件生成记录了 21 次工具调用，全部带参数。**不返回**：系统提示词、模型文字输出、题干以外的题目内容（答案、解析、隐藏测试、参考解）、Key。用于书带和执行记录。

**生成中的实时性**：后端只在每条消息结束时保存会话，所以轨迹以“一次工具调用”为单位更新，延迟 1–2 秒，不是逐字流式。这对展示“Agent 在读哪里”足够；不为此改动 Agent 主循环。并发读写时 SQLite 需启用 WAL 模式（实施时确认当前设置）。

### 8.3 助教对话

`POST /sessions/{id}/tutor`：Vercel AI SDK `streamText` + `toUIMessageStreamResponse`。

- 上下文：当前课件正文与引用、当前知识点、用户选中的段落。
- 工具：`search_sources`、`read_source`（只限本课程版本已授权的来源，复用 `createSourceTools`）。
- 回答要求附段号；前端把段号渲染为可回查的朱批出处。
- **防泄题**：当前有未作答题目时，助教的上下文不包含题目答案和解析；系统提示要求不直接给出当前题答案。
- 对话不写入掌握证据，也不写入数据库。本地模式用设置页的 Key，线上模式用请求头里的 Key。

### 8.4 线上模式（`VL_MODE=online`）

同一份代码，环境变量切换：

| 方面 | 本地模式（默认） | 线上模式 |
|---|---|---|
| 访问 | 仅 `127.0.0.1:3101` 同源 | 配置的公网域名（`VL_PUBLIC_ORIGIN`），HTTPS，同源校验改为该域名 |
| 访问码 | 终端生成的口令 | 部署时设置的访问码（`VL_ACCESS_CODE`），评审材料里附上 |
| 数据空间 | 固定 `local-owner` | 每个浏览器第一次用访问码登录时新建一个空间（随机 ID）。服务器发两个 HttpOnly cookie：登录 cookie（30 天）和空间 cookie（90 天）。登录过期后重新输入访问码，只要空间 cookie 还在就回到原空间；清除浏览器数据后是新空间 |
| 示例内容 | 无 | 新空间自动复制一门预置示例课程（来源快照、课程版本、已生成的课件与题组、生成过程轨迹），评委不填 Key 也能浏览、答题、看生成回放。示例由一个种子脚本从一个已生成好的模板空间导出、再按空间复制（保持各表的外键与修订号一致）。超出示例已生成的部分（如后续知识点），继续学习时需要填 Key |
| 模型配置 | 设置页存数据库 | 浏览器 localStorage（zustand persist）；只在需要模型的请求里放在请求头 `X-VL-Model` 中发送：发起生成、继续任务、生成补练、开始需要生成内容的活动、助教对话、拉取模型列表。其余请求不带 |
| Key 在服务器的生命周期 | — | 生成任务：按任务 ID 存进程内存，任务结束、取消、失败即删除；助教对话：只在单次请求内使用；进程重启即消失 |
| 判题与审校 | — | 客观题本地比对、编程题走 Judge0，均不需要 Key；题目的模型审校在生成任务内完成，使用该任务的 Key |
| 设置接口 | 读写数据库 | 禁止写入；模型列表查询用请求中的 Key |
| 上传限制 | 50MiB | 20MiB/本，每空间 10 本 |
| 并发与配额 | 不限 | 每空间同时 1 个生成任务；每空间每天最多 20 次生成；全站同时最多 6 个生成任务，超出排队 |
| 登录尝试 | 每分钟 5 次 | 按 IP 每分钟 5 次 |
| 空间清理 | — | 30 天未访问的空间及其上传文件自动删除 |

示例课程的教材必须可公开：用 Python 官方中文教程（PSF 许可）和 OI Wiki（CC BY-SA 4.0）的页面，页脚注明来源与许可。当前开发库里的《Python编程：从入门到实践》来自 z-library，不能出现在线上站和演示视频里。

### 8.5 服务器重启后的任务

线上模式下进程重启，内存里的 Key 消失。运行中的任务租约到期后变为可恢复；前端显示“服务器已重启，请在设置中确认 Key 后点继续”，用户继续时请求带上 Key。已验收的知识点、小节、题目不重复生成（后端已支持断点续跑）。

## 9. 安全

- Key 不进入：数据库、`vl_jobs.input_json`、Agent 会话记录、日志、错误信息、SSE 事件、URL。错误遮蔽沿用 `provider-error.ts`，并加入请求中的 Key。
- 浏览器存 Key 的风险：同一浏览器的脚本能读取 localStorage。缓解：严格 CSP（禁止内联脚本、只允许本站资源）、Markdown 渲染不执行 HTML（现有）、不引入第三方脚本；设置页说明“共用电脑用完请点清除 Key”。
- 空间隔离：所有查询已按 `scope_id` 过滤；新增测试覆盖跨空间访问被拒绝。上传文件按空间分目录。
- 线上模式的联网补充资料：沿用现有公网地址校验（禁止内网、本机、保留地址，逐跳校验重定向）。
- 编程题判题：沿用 Judge0 隔离执行。注意：生成编程题时参考解也要过 Judge0，没有 Judge0 就生成不出编程题（选择题、填空题不受影响）。编程题是计算机类课程的亮点，线上站应部署 Judge0；未部署时界面明确显示“判题服务未配置”，绝不在主机执行代码。

## 10. 部署

国内服务器（域名已备案）：

- Node 22+ 运行 `next build && next start`，进程守护用 systemd（或 PM2）。
- Nginx 反向代理 + HTTPS 证书；SSE 路径关闭代理缓冲（`proxy_buffering off`）。
