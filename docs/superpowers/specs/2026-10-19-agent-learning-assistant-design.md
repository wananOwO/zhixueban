## 1. 意图与为什么

### 痛点

现有 AI 学习工具（DeepTutor、edu-agent、Reviva、PageLM 等）已能做教材导入与大纲/测验生成，
DeepTutor 甚至已有“目标＋材料→学习路径”。但它们缺的是**让每一次课程调整和掌握判断都可检查的机制**：
比如"我要参加算法比赛，只需这本 Python 教程里的语法和算法部分"——现有工具可以裁剪大纲，
但不能按先修依赖重排、不能发现教材内容与目标的缺口、不能保证出的题只用已学内容可解、
更不能用执行结果而非模型自评来证明"真的学会了"。

### 产品一句话

导入一本教材 → 告诉 Agent「学什么、怎么教」→ 得到一门为你定制的课，
学完即考，考到会为止。

### 为什么现在做（参赛契合度）

10037 赛道评分表中「AI 技术深度」占 35%，其子项 Agent(8%) + RAG(6%) +
MCP/工具集成(4%) + 多模态(5%) 共 23%，与本项目功能逐项对应；
官方推荐选题方向第 5 条即「AI 教育与学习平台」。

## 2. 目标 / 非目标 / 反目标

### 目标（Goals）

1. **目标驱动课程重组**：用户输入学习目标 + 课程设计提示词，Agent 对教材知识图谱做裁剪、
   重排、深浅调节，生成个性化课程大纲。这是核心创新点，必须做好。
2. **三种学习模式**（见 §5.3），学完即考，出题硬约束"仅用已学内容可解"。
3. **教材为中心、不锁死模型**的 RAG 策略（见 §5.2）。
4. **学科专家提示词系统**：内置 + 用户自定义（见 §5.4）。
5. 掌握度可视化：热力图 + 知识图谱着色；笔记与 Obsidian 双向同步。
6. 满足赛道全部提交物要求（见 §7），评审演示路径顺畅。

### 非目标（Non-goals）

- 多用户 / 账号体系 / 服务端协同 —— 定位个人学习助手，单用户本地部署
- 移动端 App —— 仅 PC Web（响应式兼顾即可）
- 班级/教师端、作业分发等 B 端功能
- 自训模型 —— 全部走商用/开源 LLM API

### 反目标（Anti-goals，做到也算失败）

- 生成内容不可信：课件出现明显幻觉且无来源标注机制
- 出题超纲：出现必须用未学内容才能解的题
- 抄袭嫌疑：任何模块直接照搬开源项目代码（赛道明文禁止，违规取消资格）
- 演示时依赖不可用：评审在线演示地址挂掉，或本地复现超过 10 分钟

## 4.1 前端设计原则（用户明确要求：前端必须好看、符合主题、无障碍到位）

**设计风格**：参考 Vercel Geist 设计体系——克制的高级灰底 + 单一强调色、细边框、大量留白、
几何无衬线字体（Geist Sans / 中文用系统字体栈）、微动效（Framer Motion，时长 ≤200ms）。
深浅双主题（next-themes），默认跟随系统。

**不重复造轮子（用户明确原则）**：能用的成熟开源组件直接用，必要时以开源组件为基底二改：

| 场景 | 选型 | 理由 |
|---|---|---|
| 基础组件 | shadcn/ui（Radix Primitives） | ARIA 无障碍内置、可复制进仓库自定义 |
| AI 对话/课件流 | assistant-ui | 专为 Vercel AI SDK 设计的聊天/流式 UI 组件 |
| 富文本笔记 | TipTap | 成熟编辑器，Markdown 序列化，插件生态 |
| 知识图谱交互 | React Flow（@xyflow/react） | 节点图交互完善（缩放/拖拽/键盘），胜过自绘 d3 |
| 命令面板 | cmdk | 全局搜索/跳转 |
| 布局 | react-resizable-panels | 可拖拽分栏 |
| 图表/热力图 | ECharts | 日历热力图内置 |

**无障碍硬性要求**（评审演示也会体现）：
1. 全站键盘可达，焦点环可见；所有交互元素有 aria-label
2. 文字对比度 ≥ WCAG AA（4.5:1）
3. 流式输出区域用 `aria-live="polite"`，屏幕阅读器可感知生成进度
4. 尊重 `prefers-reduced-motion`，开启时禁用非必要动效
5. 知识图谱等图形区域提供等价的列表/文本视图

## 5. 功能设计

### 5.1 教材导入与解析管线

支持格式：**EPUB、TXT、PDF、MOBI、AZW3、DOCX、Markdown**。

管线：

```
原始文件 → 格式解析层（epubjs / 自研 TXT 章节切分 / pdf 解析 / mammoth(docx) 等）
        → 统一中间表示「章节树」：{ 标题层级, 段落, 图片, 原始位置锚点 }
        → 两个消费者：① 向量分块入 RAG 库  ② Agent 读章节树生成知识图谱
```

- MOBI/AZW3 若无合适的 JS 解析库，转换层可调用 calibre 的 `ebook-convert`（作为可选外部依赖，
  复现文档中说明安装方式）；保底先转 EPUB 再走统一管线。
- 每个段落保留**位置锚点**（章节 + 偏移），供来源标注跳回教材原文。

### 5.2 RAG 策略：教材为中心，可追溯，不承诺"接了就无幻觉"

- 生成课件时检索教材相关分块作为**上下文锚点**；允许模型补充教材外讲解——教材是地基不是天花板。
- **来源分级**：
  1. 主教材（课程范围的主要依据）
  2. 补充知识库（个人笔记、其他资料、Obsidian 导入内容）
  3. 外部技术资料（搜索/MCP 获取，保存来源与获取时间）
  4. 模型生成内容（类比、改写、练习，明确标注性质）
- 课件中引用教材的部分标注来源徽标（可点击跳回教材位置，保存章节/段落锚点）；
  外部资料与教材冲突时展示差异，不悄悄覆盖。
- 整书解析、建索引、课件生成作为**可恢复的后台任务**：有进度、可重试、结果缓存，
  浏览器刷新后不重复创建（jobs 表）。

### 5.3 三种学习模式（共享同一份学习记录）

**状态定义**（全局统一，不得混用）：
- `locked` 未解锁：前置知识未达标，不可进入
- `unlocked` 已解锁：可学习
- `learned` 已学习：看过讲解（与是否掌握无关）
- `mastered` 已掌握：掌握度 ≥ 0.8

| 模式 | 流程 |
|---|---|
| ① 理论学习 | 章节讲解 → 章末测评（默认 10 题，可调） |
| ② 边学边练 | 每知识点讲解 + n 道练习（默认 3）→ **"做完"与"达标"分开**，默认做完即解锁下一个（达标阈值可配置）→ 章末测评 |
| ③ 刷题模式 | 不讲解，按知识点出题 → 全部考完后出综合大题；无学习记录的新用户先做**简短诊断**或声明基础以建立出题范围，证据来源标注（诊断/声明/历史记录） |

**切换规则**：学习中途可随时切换模式，已学内容、答题记录、笔记全部保留，只重排后续步骤。
修改目标或大纲 = 产生课程新版本（course 表 version 字段），历史版本与成绩保留。
题量/难度/达标阈值存 courses 表，支持按章节覆盖默认值。
**难度定义**：提高难度 = 增加组合与推理要求，**不得**悄悄引入未学知识。

**出题硬约束**：见 §5.3 生成—校验—发布流程（§5.8）。

### 5.4 学科专家提示词系统

- 课件生成前选择学科类型，注入对应专家提示词，控制讲解风格：
  - 计算机类：重代码示例、可运行片段、上机练习
  - 数学类：重定义-定理-证明链条、推导步骤
  - 物理类：重直觉类比 + 公式推导 + 单位量纲
  - 生物类：重图示、结构-功能对应、记忆框架
  - 语言类：重例句、对比、渐进词汇
  - 通用类：默认
- 内置提示词存仓库 `prompts/` 目录（Markdown + frontmatter），用户可在 UI 中
  **新建 / 编辑 / 导入 / 导出**自己的提示词模板，存本地数据库。
- 学习目标提示词与学科提示词是两层：学科定"怎么讲"，目标定"讲哪些、讲多深"。

### 5.5 课程生成（核心流程）

```
导入教材 → Agent 解析章节树 → 生成全量知识图谱（知识点 + 前置依赖边）
→ 用户填：学习目标 + 课程设计提示词 + 学科类型
→ 生成「学习约定」结构化配置（目标/当前基础/内容边界/教学偏好/测评设置/补充资料策略），用户可编辑
→ Agent 按先修依赖编课：裁剪以知识点为单位而非整章删除
  （被排除章节中首次出现的必要知识点须提取出来、替换练习场景后保留）
→ **教材缺口检测**：目标要求但教材未覆盖的内容明确列出，用户确认补充资料或调整目标
→ 生成个性化课程大纲 → 课程确认页解释四件事：保留了什么、跳过了什么、为什么重排、补充了什么
→ 用户确认/手调 → 逐章生成课件
```

### 5.6 可视化与笔记

- **掌握度模型**：每个知识点维护掌握度分数（由答题结果更新，公式见 §8.5）。
- **热力图**：日历式学习热力图（学习时长/答题量），使用真实学习记录而非演示数据。
- **知识图谱**：@xyflow/react 交互图，节点按掌握度着色（绿≥0.8/黄0.4-0.8/红<0.4/灰未解锁）；
  "先修/相关/引用"三种边分开展示；附等价列表视图（无障碍）。
- **学习笔记**：每个知识点可记笔记（TipTap 富文本/Markdown）。
- **课件内容**：受约束内容块——Markdown、LaTeX 公式、代码高亮、图片、视频卡片、预定义交互组件；
  **模型只生成内容与组件参数，不直接输出可执行页面代码**（不用 MDX 直渲染，避免不可信内容执行风险）。
  Agent 可通过 MCP 收集外部素材（配图、参考视频），素材标注来源与获取时间。

### 5.6.1 Obsidian 边界（首版范围收敛）

Obsidian Vault 是本地文件夹；VPS 部署时配置的“vault 路径”读到的是 VPS 的文件系统，不是用户电脑。
因此首版范围：
- **导入**：上传 vault 目录打包（zip）或本地路径（仅本地部署时），内容入 RAG 库作补充知识源
- **导出**：学习笔记可导出为 Markdown（下载或本地部署时写入 vault 目录）
- **实时双向同步后置**：冲突、重命名、删除的完整处理放到后续版本
- 核心课程、成绩、掌握度存应用内 SQLite，不依赖 vault 是否在线

### 5.6.2 公网演示模式（访问边界）

VPS 公开演示时启用 `DEMO_MODE=true`：
- 管理员配置（LLM key/MCP/路径）与评审体验分离，体验者不可改设置
- 使用预配置的只读 MCP 工具，不开放任意命令与连接器配置
- 模型调用限额、上传大小限制、演示数据定时重置
- 体验者数据按会话隔离，互不可见

### 5.7 MCP 接入

- 内置 MCP client（`@ai-sdk/mcp` 的 `createMCPClient`），用户在设置中配置 server。
- **首版仅接入只读工具**（搜索、文档查询、arXiv 等），不开放命令执行与任意文件写入。
- Agent 生成课件/答疑时调用 MCP 获取最新资料；UI 展示"调用了什么工具、获得哪些资料、如何用于课件"，不伪造模型思考过程。
- 连接失败时降级使用已有资料，并明确提示资料时效。

### 5.8 出题：生成—校验—发布（评审修订核心）

不信任模型自报的标签。出题与验题拆开：

```
确定目标知识点 + 允许使用的先修知识
→ 生成：题干、参考解法、答案、评分标准、测试用例（编程题）
→ 校验：独立检查参考解法实际依赖的知识 ⊆ 已解锁集合；校验答案与解法一致性
→ 编程题：执行器运行参考解 + 测试用例，全部通过才入库
→ 合格题入题库 → 发布给学习者
```

- **题目质量验证**（题本身对不对）与**用户答案判分**（用户答得对不对）是两件事，分开实现。
- 编程题判分：执行器跑测试用例负责对错；LLM 负责解释错误、给分层提示
  （概念提醒 → 思路提示 → 局部步骤 → 完整解析）。主观题才用评分量表 + 模型评价。
- 执行器：Judge0（VPS Docker 自部署）判 Python 等；JS 题走 node:vm 本地执行兑底。
- 缺少可靠验证手段的题型显示"验证等级"，不把未确认的判断当成确定的掌握证据。
- 使用提示与独立作答在学习记录中留下不同证据。

## 8.5 构建者自检补充（AI 拍板，标准实现即可）

1. **判题分工**：客观题本地比对；编程题由执行器跑测试用例判对错，LLM 只负责解释与分层提示；
   主观题用评分量表 + LLM 评价，分数回写掌握度（见 §5.8）。
2. **掌握度公式**：答对 `m' = 1-(1-m)*0.5`，答错 `m' = m*0.5`，再乘时间衰减 `exp(-Δdays/30)`；
   初值 0，连对 3 次得 0.875 ≥ 0.8 掌握阈值。
3. **Obsidian 冲突**：首版仅导入/导出，无双向同步（见 §5.6.1）；冲突处理后置。
4. **题目持久化**：出题即落库（Question 表），同一知识点重做优先取库存未答题，不足再生成——控制 API 成本。
5. **版本锁定**：Node ≥22、Next.js 15+（实际 16）、MCP 用 `@ai-sdk/mcp`。

## 9. 留给实现者的开放点

1. 向量库在 LanceDB 与 sqlite-vec 之间二选一——实现者按集成便利度定，VPS 上均可嵌入运行。
2. Agent 编排手写状态机 vs 引入 LangGraph.js——按复杂度取舍，优先简单。
3. PDF 解析库选型（pdfjs-dist 直接抽文本 vs 外部服务）——注意扫描版 PDF 无文本层的降级提示。
4. 知识图谱布局算法细节。
5. LLM 默认 Provider 与模型型号——以免费额度充足、国内可直连为先。

## 10. 本设计中由 AI 助手代为拍板、需用户复核的决策

1. 内置学科提示词定为 6 类（计算机/数学/物理/生物/语言/通用）。
2. 掌握度模型采用"连对指数收敛 + 答错减半 + 时间衰减"（公式见 §8.5），不引入 FSRS 等复杂算法。
3. 在线演示用自有 VPS 全栈部署 + 内置示例教材（规避版权教材上传公开仓库的风险）。
4. MOBI/AZW3 依赖 calibre 外部工具转换，列为可选依赖而非核心管线。
