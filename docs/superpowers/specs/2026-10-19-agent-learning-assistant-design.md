## 1. 意图与为什么

### 痛点

现有 AI 学习工具（DeepTutor、edu-agent、Reviva、PageLM 等）都是「教材有什么就教什么」：
按教材原始结构生成大纲、quiz、闪卡。但真实学习者的目标是**外部驱动**的——
比如"我要参加算法比赛，只需这本 Python 教程里的语法和算法部分，小游戏章节跳过，
而且从完全零基础讲起"。现有工具无法按学习目标对教材做裁剪、重排和深浅调节。

### 产品一句话

导入一本教材 → 告诉 Agent「学什么、怎么教」→ 得到一门为你定制的课，
学完即考，考到会为止。

### 为什么现在做（参赛契合度）

10037 赛道评分表中「AI 技术深度」占 35%，其子项 Agent(8%) + RAG(6%) +
MCP/工具集成(4%) + 多模态(5%) 共 23%，与本项目功能逐项对应；
官方推荐选题方向第 5 条即「AI 教育与学习平台」。

## 2. 目标 / 非目标 / 反目标

### 目标（Goals）

1. **目标驱动课程重组**：用户输入学习目标 + 课程设计提示词，Agent 对教材知识图谱做裁剪、
   重排、深浅调节，生成个性化课程大纲。这是核心创新点，必须做好。
2. **三种学习模式**（见 §5.3），学完即考，出题硬约束"仅用已学内容可解"。
3. **教材为中心、不锁死模型**的 RAG 策略（见 §5.2）。
4. **学科专家提示词系统**：内置 + 用户自定义（见 §5.4）。
5. 掌握度可视化：热力图 + 知识图谱着色；笔记与 Obsidian 双向同步。
6. 满足赛道全部提交物要求（见 §7），评审演示路径顺畅。

### 非目标（Non-goals）

- 多用户 / 账号体系 / 服务端协同 —— 定位个人学习助手，单用户本地部署
- 移动端 App —— 仅 PC Web（响应式兼顾即可）
- 班级/教师端、作业分发等 B 端功能
- 自训模型 —— 全部走商用/开源 LLM API

### 反目标（Anti-goals，做到也算失败）

- 生成内容不可信：课件出现明显幻觉且无来源标注机制
- 出题超纲：出现必须用未学内容才能解的题
- 抄袭嫌疑：任何模块直接照搬开源项目代码（赛道明文禁止，违规取消资格）
- 演示时依赖不可用：评审在线演示地址挂掉，或本地复现超过 10 分钟

## 5. 功能设计

### 5.1 教材导入与解析管线

支持格式：**EPUB、TXT、PDF、MOBI、AZW3、DOCX、Markdown**。

管线：

```
原始文件 → 格式解析层（epubjs / 自研 TXT 章节切分 / pdf 解析 / mammoth(docx) 等）
        → 统一中间表示「章节树」：{ 标题层级, 段落, 图片, 原始位置锚点 }
        → 两个消费者：① 向量分块入 RAG 库  ② Agent 读章节树生成知识图谱
```

- MOBI/AZW3 若无合适的 JS 解析库，转换层可调用 calibre 的 `ebook-convert`（作为可选外部依赖，
  复现文档中说明安装方式）；保底先转 EPUB 再走统一管线。
- 每个段落保留**位置锚点**（章节 + 偏移），供来源标注跳回教材原文。

### 5.2 RAG 策略：教材为中心，不锁死模型

- 生成课件时，检索教材中与当前知识点相关的分块，作为**上下文锚点**注入，防止跑偏和幻觉。
- 模型**允许并鼓励**补充教材外的讲解、类比、示例——教材是地基不是天花板。
- 课件中引用教材原文的部分**标注来源徽标**，点击跳回教材对应位置；模型自由发挥部分不标注，
  用户一眼区分"书上说的"和"AI 补充的"。
- 知识库来源可扩展：除教材外，允许挂接 **Obsidian vault** 作为 RAG 数据源（可选）。

### 5.3 三种学习模式

课件生成前，用户选择学习类型（学科，见 §5.4）与学习模式：

| 模式 | 流程 |
|---|---|
| ① 理论学习 | 章节讲解 → 章末聚合出题考验（默认 10 题，可调） |
| ② 边学边练 | 每个知识点讲解 + n 道示例题（默认 3，可调），当前知识点过关才解锁下一个 → 章末再聚合出题 |
| ③ 刷题模式 | 不讲解，直接按知识点各出 n 题 → 全部知识点考完后出 n 道综合大题 |

**出题硬约束**：所有题目必须仅用「用户已学完的内容」可解。实现方式：出题 Agent 的上下文中
只注入已解锁知识点的内容，并在提示词中显式约束；判题 Agent 判错时将对应知识点回流入复习队列。
难度由用户设置（入门/中等/困难），作用于出题提示词。

### 5.4 学科专家提示词系统

- 课件生成前选择学科类型，注入对应专家提示词，控制讲解风格：
  - 计算机类：重代码示例、可运行片段、上机练习
  - 数学类：重定义-定理-证明链条、推导步骤
  - 物理类：重直觉类比 + 公式推导 + 单位量纲
  - 生物类：重图示、结构-功能对应、记忆框架
  - 语言类：重例句、对比、渐进词汇
  - 通用类：默认
- 内置提示词存仓库 `prompts/` 目录（Markdown + frontmatter），用户可在 UI 中
  **新建 / 编辑 / 导入 / 导出**自己的提示词模板，存本地数据库。
- 学习目标提示词与学科提示词是两层：学科定"怎么讲"，目标定"讲哪些、讲多深"。

### 5.5 课程生成（核心流程）

```
导入教材 → Agent 解析章节树 → 生成全量知识图谱（知识点 + 前置依赖边）
→ 用户填：学习目标 + 课程设计提示词 + 学科类型
→ Agent 对知识图谱做裁剪（去掉无关子树）、重排（按依赖拓扑 + 目标优先级）、
  深浅调节（目标内知识点展开更细，标注"零基础"则增加前置补充节点）
→ 生成个性化课程大纲 → 用户确认/手调 → 逐章生成课件
```

### 5.6 可视化与笔记

- **掌握度模型**：每个知识点维护掌握度分数（由答题结果更新，简单加权 + 时间衰减）。
- **热力图**：日历式学习热力图（学习时长/答题量）。
- **知识图谱**：力导向图，节点按掌握度着色（绿=掌握 / 黄=在学 / 红=薄弱 / 灰=未解锁）。
- **学习笔记**：每个知识点可记笔记（富文本/Markdown）；可选**双向同步到 Obsidian vault**
  （写入 vault 目录的 Markdown 文件，监听变更回读）。
- **课件富文本**：支持 Markdown、LaTeX 公式、代码高亮、图片、嵌入视频；
  Agent 可通过 MCP 搜索收集外部素材（配图、参考视频链接）加入课件，素材标注来源。

### 5.7 MCP 接入

- 内置 MCP client，用户在设置中配置 MCP server（搜索、文档、arXiv 等）。
- Agent 在生成课件/答疑时可调用 MCP 工具获取最新技术资料，调用过程在 UI 中可视化
  （对应评分项"AI 思考状态可视化"）。

## 8.5 构建者自检补充（AI 拍板，标准实现即可）

1. **判题**：客观题（选择/填空）本地比对；主观题（编程/简答）由判题 Agent 按"标准答案 + 评分要点"LLM 判分并给评语，分数回写掌握度。
2. **Obsidian 同步冲突**：以文件 mtime 新者为准，冲突时保留两份（应用内笔记加 `.conflict` 副本），不做三路合并。
3. **题目持久化**：出题即落库（Question 表），同一知识点重做时优先从未答过的库存题取，不足再新生成——控制 API 成本。

## 9. 留给实现者的开放点

1. 向量库在 LanceDB 与 sqlite-vec 之间二选一——实现者按集成便利度定，VPS 上均可嵌入运行。
2. Agent 编排手写状态机 vs 引入 LangGraph.js——按复杂度取舍，优先简单。
3. PDF 解析库选型（pdfjs-dist 直接抽文本 vs 外部服务）——注意扫描版 PDF 无文本层的降级提示。
4. 知识图谱布局算法细节。
5. LLM 默认 Provider 与模型型号——以免费额度充足、国内可直连为先。

## 10. 本设计中由 AI 助手代为拍板、需用户复核的决策

1. 内置学科提示词定为 6 类（计算机/数学/物理/生物/语言/通用）。
2. 掌握度模型采用"答题加权 + 时间衰减"的简单方案，不引入 FSRS 等复杂算法。
3. 在线演示用自有 VPS 全栈部署 + 内置示例教材（规避版权教材上传公开仓库的风险）。
4. MOBI/AZW3 依赖 calibre 外部工具转换，列为可选依赖而非核心管线。
