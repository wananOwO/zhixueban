# 学习 Agent 实施计划

**依据：** `docs/superpowers/specs/2026-10-23-learning-agent-design.md`；用户已确认按学习活动生成、允许联网补充、授权当前模型一次小范围真实验收最多30次请求。

**架构：** 直接使用固定版 pi-agent-core/pi-ai。学习服务仍负责scope/任务/课程状态；Agent负责工具选择和纠错；工具内部做结构、来源、数量与领域验证，通过终验后发布。无需重新确认执行方式，不提交Git。

1. [ ] `agent/runtime.ts`、`agent/provider.ts`：Pi实例、tool result错误反馈、完成门槛、取消、事件；测试无提交不能成功、错误工具修正、截断不执行。
2. [ ] `agent/source-tools.ts`、`agent/web.ts`：目录/搜索/分页原文及公开网页搜索提取，受控HTTP地址、正文快照、无任意文件/执行工具；测试引用/分页/网页安全边界。
3. [ ] `agent/learning-agent.ts` 与课程/学习服务：分项提交方案/课件/题目，来源和内容验收反馈同会话；可恢复产物与会话存储（显式v4迁移）。从普通Chat切到Agent，删除不再使用的旧模型生成逻辑；现有业务语义不变。
4. [ ] jobs/events与前端：工具阶段、自动纠错、暂停/恢复与取消，进度不暴露隐藏题目内容；测试持久化、幂等、恢复及浏览器。
5. [ ] 全量/类型/构建审查；执行一次真实知识点课件验收（共最多30次模型请求），记录真实请求数和验收结果，不自动扩展到整课。

边界：不将供应商永久故障假报成功；不固定3次纠错失败、不恢复60秒生成超时或80,000字教材门槛；保留用户数据与无关未提交修改。迁移先在临时库验证，再由用户显式初始化开发库。真实验收使用独立测试库且复用已配置模型凭据，不输出密钥。
