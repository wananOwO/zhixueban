## 融合方案中已确认的使用行为

- 用户已确认：再次打开课程时回到上次学习位置；能自由查看以前的课件、做过的题和答案解析；回看不改变当前进度、不重复记分。

## 融合设计最终确认与新实施调研

- 用户已明确确认融合设计，要求加入 C；语言范围为 Python 3、JavaScript、C。不包含 C++。编译错误单独反馈，编译和运行都必须隔离。
- 使用 Context7 与 GitHub CLI 查询 Judge0 官方仓库，发布 API 当前返回 v1.13.1；该版本修复 <=1.13.0 的三个严重沙箱逃逸/SSRF 漏洞，不使用旧版本或浮动 latest。
- 官方 v1.13.1 仅正式测试 Linux，推荐 Ubuntu 22.04、cgroups v1；官方 compose 含 privileged server/worker 与独立 Redis/Postgres。Windows 有 Docker CLI 并不意味着可直接、安全、完整运行。计划必须包含环境预检/人工部署门槛，不自动修改系统或启动高权限容器。
- 官方配置明确 wall_time_limit 单位为秒，Context7 摘录出现毫秒说明冲突；实现以固定版本官方配置/API 源码为准。语言 ID 应从实际服务 /languages 核对并固定，不能凭训练记忆硬编码 C/Python/JS 版本。
- `docker info` 只读预检返回 dockerDesktopLinuxEngine named pipe 不存在（引擎未运行/不可达）；本轮未尝试启动或修改设置。真实判题验收是环境待办，不阻塞计划编写。
- 三语言统一采用单文件标准输入/输出题面与测试数据，不把现有 JavaScript assert 字符串拼到 Python/C。编译错误单独映射，内存超限只能根据执行器确证信息，不能把所有 SIGSEGV 当内存超限。
- 外部 Judge0 提交没有天然 exactly-once：若 POST 已接收却丢 token，保存 unknown 状态、不自动重投；已有 token 重启后继续查询。本地记分/证据必须事务且幂等，不承诺外部执行绝不重复。
- 当前 RAG store 存在全局 chunk ID 和向量维度绑定风险；教材库删除还必须删除对应 chunk_vectors rowid；增强导入应使用自有来源/检索存储或范围隔离适配，不能直接继承旧多书冲突。
